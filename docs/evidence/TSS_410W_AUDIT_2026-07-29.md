# Audit — herberekening belastingscores rond de achterhaalde 410W-FTP (taak #387)

Datum: 2026-07-29 · Omgeving: **productie** · Volledige rij-export: `TSS_410W_AUDIT_2026-07-29.csv`

## Aanleiding

`ftp_history` id 8 van de tweede productiegebruiker bevatte 410 W (`derived`, 2026-05-25) met
notes `"ACHTERHAALD — niet gebruiken als actuele FTP…"` — een formaat dat **niet** matcht op
het bestaande `[achterhaald]%`-filter in `derived-load-backfill.ts`. Daardoor werd 410 W nog
als historische FTP-op-datum gebruikt voor alle 182 sessies van die gebruiker vóór 26 juni.

Besluit (René, 2026-07-29): markeer de rij als `[achterhaald]` (zelfde conventie als de 331W-rij,
taak #382) en herbereken de 182 belastingscores via de bestaande centrale engine. Geen tweede
berekeningspad — de backfill-engine doet het werk zodra de rijen genulleerd zijn.

## Aanpak

1. `repair-410w-ftp.ts` (idempotent, atomic):
   - Controle: als id 8 al `[achterhaald]%` heeft → skip.
   - Transactie: prefix notes met `[achterhaald] ` + NULL uit de 182 TSS-rijen.
2. Hook vóór `backfillDerivedLoad` in `index.ts` — de engine herleid ze direct.

## Idempotentie

- De repair controleert vóór elke run of de notes al beginnen met `[achterhaald]` — bij een
  tweede run is de `UPDATE ftp_history` een no-op.
- `backfillDerivedLoad` werkt alleen op `tss IS NULL` — herberekend = idempotent no-op.
- Profiel-FTP blijft **345 W** (`ftp_estimated=false`); geen FTP-waarde,
  historie of trainingsinhoud anders aangeraakt. Cross-user: niets aangeraakt.

## Filterformat geharmoniseerd

De bestaande engine-markering (`[achterhaald] `) is nu de enige convention. De notes van id 8
worden geprefixed met `[achterhaald] `; de oorspronkelijke tekst blijft als leesbare toelichting.
Dit voorkomt dat een toekomstige handmatige notitie het filter opnieuw omzeilt.
