Redesign the Sparki athlete experience around intelligent day types instead of static dashboards.

The athlete must immediately understand:
- What today is.
- Why.
- What Sparki expects.
- What the next action is.

The UI should adapt automatically depending on the current day type.

Create the following Day Types:

• Training Day
• Recovery Day
• Rest Day
• Day Before Race
• Race Day
• Travel Day
• Sick / Injury Day

Each day type receives its own homepage while using the same visual design language.

----------------------------------------
1. TRAINING DAY
----------------------------------------

If Sparki created the training:

Show:
- Today's training
- Why this training
- Expected benefit
- What Sparki sees
- Start Training

If an external coach created the training:

Clearly distinguish:

Coach says:
- Planned training
- Coach notes (if available)

Sparki explains:
- Why this training is likely planned
- Weather advice
- Nutrition
- Hydration
- Recovery status
- Expected training load
- Route recommendation
- Best departure time

Never replace the coach.
Sparki always supports the coach.

If no coach notes exist,
state clearly that Sparki is interpreting the purpose of the training.

----------------------------------------
2. NO TRAINING AVAILABLE
----------------------------------------

If no training exists:

Do NOT leave the athlete on an empty screen.

Instead show:

- Recovery status
- Sleep
- Weather
- Nutrition
- Suggestions
- Recovery advice
- Mobility
- Optional training suggestions

----------------------------------------

Every homepage must answer:

Why?

One clear primary action only.

The athlete should never feel lost after opening the app.
