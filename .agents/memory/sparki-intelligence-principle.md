# Sparki page-intelligence principle

**Rule:** no athlete-facing surface may be a passive list / table / card / map.
Every page must (1) be personalized to the athlete's profile and intent, (2) be
interactive, and (3) carry Sparki's own judgment / added value — not just render
rows. If a page only shows data the user typed or fetched, with no Sparki
reasoning on top, it is "een domme kaart" and must be rethought.

**Concrete expectations the user has stated:**
- Content must be FILTERED to the athlete's type/intent. Example: the
  wedstrijdkalender must show competition calendars (KNWU / We-Tri) to a
  wedstrijdsporter and touring calendars (Fietssport-toertochten) to a toerrenner
  — never both to everyone. A single "recommended" default while still listing
  every source is NOT enough; the irrelevant ones must move out of the way (behind
  a discrete "andere kalenders", honest, not deleted).
- Sparki must proactively SUGGEST and JUDGE (which race fits your goal / level /
  timing, clashes with your plan, why it fits), not just offer a search box.
- Import / edit flows must auto-GATHER all available data from the source (and,
  if needed, extra lookups: detail page, GPX → distance/elevation/profile, start
  time) and present a REVIEW of "gevonden vs ontbreekt", asking the athlete only
  for genuine gaps — never a blank fill-in form. Sparki haalt en beoordeelt, de
  atleet bevestigt.

**Why:** the user is repeatedly frustrated that pages are "dumb" — they show data
but no intelligence or personalization, which is the entire point of Sparki.

**How to apply:** when building or reviewing ANY athlete surface, ask: is it
filtered to this athlete, is it interactive, and does Sparki add a real judgment?
All additions stay honest — real data or an explicit "weet ik niet", never
fabricated depth.
